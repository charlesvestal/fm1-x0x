# X0X for the FM-1 — design

Standalone firmware for the M-VAVE FM-1: a TR-909 drum machine (the 9W9 voices),
two TB-303s (Open303), each with its own TB-3PO acid generator, a breakbeat
generator, and 16 patterns.
Built on Felucca's platform layer (HAL, USB, update loader, flash storage, LCD),
which is kept; Felucca's instrument (engines, tracks, UI, editor) is replaced.

Licence: GPL-3.0-only, as Felucca, 9W9 (er-99) and schwung-tb3po. Open303 is MIT.

## Hardware this is designed against

Facts from Felucca's HAL and linker script; nothing here is measured on a device yet.

| | |
|---|---|
| CPU | JieLi AC79 (pi32v2, `-mcpu=r3`), **single-precision FPU** (`-mfprev1`, operates on the GPRs, so no extra ISR state). Doubles are software |
| RAM | 96 KiB `.data/.bss`, 336 KiB `.pool`, stacks above |
| Flash | app slot 0x8DFBC (581 KiB) executes in place |
| Screen | 240 x 240 RGB565 (ST7789 class) |
| Keys | 27: 16 white, 11 black (ids 14..40) |
| Encoders | SELECT, ALGORITHM, PRESETS, KNOB 1..4 (relative, no push) |
| Buttons | FX SCL ENV LFO EDIT GLO HOME SAVE ARP SEQ PLAY REC OCT- OCT+ |
| Pot | MASTER (ADC), volume |
| Audio | 44.1 kHz, I2S, 256-frame half buffers (5.8 ms) |

## Instrument

Four parts, always running:

- **DRUM** — 9W9: BD SD LT MT HT RS CP CH OH CR RD, one per **black key**, with the
  909 panel's pots per voice (Tune, Tone/Attack, Decay, Snappy, Level...), per-voice
  drive, the kit's reverb and delay sends and master drive/glue.
- **303 A** and **303 B** — two independent Open303 instances (with the Devilfish
  ranges): cutoff, resonance, env mod, decay, accent, waveform, tuning, slide time,
  drive, volume, sends. Each has its own sound, its own line and its own TB-3PO.
- **BREAK** — a breakbeat generator: a loop cut into 8 slices, recombined every beat
  by Complexity (random swaps), Anchor (kick/snare slices kept on beats 1 and 3),
  Roll (repeat / walk to a neighbour slice), Fill (the last bar of a phrase breaks
  the rules), Retrig 2x/3x/4x/8x odds, Phrase (2/4/8/16 bars) and a B loop swapped in
  on the fill bar. Ported from mestela's schwung-breakbeat (BB Gen), **used with the
  author's permission** (that repository carries no licence file; the permission is
  what allows its code into this GPL-3.0 firmware — a licence file upstream would make
  it explicit). Live layer on the black keys: 8 slice keys (momentary) + reverse / half-speed
  / stutter macros.
  Audio: the loops are user samples, uploaded over USB into Felucca's three flash
  sample slots (80 KiB each, IMA ADPCM at 22.05 kHz, ~7 s: two bars at 70 BPM and up).
  Commercial breaks are not shipped. The built-in default loop is rendered at build
  time from this firmware's own 909 kit.

**16 patterns**, one per white key. A pattern holds all four parts:

- drum: 11 instruments x 32 steps (on/off), an ACCENT row, length 1..32
- 303 A and 303 B, each: 32 steps of {note, octave, gate (rest/note/tie), accent,
  slide}, length 1..32 (lengths are independent: polymeter is allowed)
- TB-3PO settings per 303: density, accent, slide, octave range, root, scale,
  direction, seed — so a pattern is reproducible from its seed
- break: on/off per step (where a bar's slices may trigger), the generator
  settings above, which slots are A and B, loop length in bars
- swing (shuffle) per pattern

Patterns switch at the end of the playing pattern (909/303 behaviour). A chain
(range a..b) plays in order.

Sound settings (the kit and both 303s' knobs) belong to the project, not the pattern.

## Panel

ALGORITHM = part (DRUM / 303 A / 303 B / BREAK), PRESETS = pattern (cued), SELECT = tempo,
KNOB 1-4 = the four values the page shows. These match the labels Felucca's
panel guide already gives those encoders.

**DRUM part**
- black key: select that instrument and play it. Recording (REC lit, playing):
  the hit is written to the nearest step.
- white key: toggle the selected instrument on that step (page = OCT-/OCT+ for
  steps 1-16 / 17-32).
- ENV held: white keys edit the ACCENT row instead.
- EDIT: the selected instrument's pots on KNOB 1-4 (EDIT again = next page).

**303 A / 303 B parts** (identical; ALGORITHM picks which one the panel edits)
- keys play the 303 live (chromatic, OCT-/OCT+ shift octave).
- SEQ: STEP view. White key selects a step (and plays it); KNOB 1 note, 2 octave,
  3 gate, 4 accent/slide. Tapping an empty step makes it a note.
- REC while stopped: step write, 303 style. Each key writes the current step and
  advances; ENV held = accent, LFO held = slide, SEQ = rest, the same key held over
  the next write = tie.
- ARP: the TB-3PO page. KNOB 1 density, 2 accent, 3 slide, 4 octave range;
  OCT+ GENERATE (new seed), OCT- MUTATE. SCL: root, scale, length, direction.
- EDIT: 303 knobs (pages: cutoff/reso/envmod/decay, accent/wave/tune/slide,
  drive/volume/rev/dly).

**BREAK part**
- black keys 1-8: play slice 1-8 while held (overrides the generator, momentary);
  9 reverse, 10 half speed, 11 stutter (while held).
- white keys: steps the break may play on (all on = the loop runs).
- KNOB pages: Complexity/Anchor/Roll/Fill, Retrig 2x/3x/4x/8x, Phrase/B chance/
  A length/B length, Level/Pitch/Rev/Dly.

**All parts**
- PLAY start/stop. HOME: pattern screen (both parts' grids). HOME held + white
  key = select pattern now; HOME held + two white keys = chain.
- FX: sends and master (reverb, delay, drive, glue). LFO page (when not used as a
  modifier): swing, accent level.
- GLO: MIDI (channels, clock in/out), save/copy/clear menu.
- SAVE: writes the project to flash. SAVE held + white key = copy the current
  pattern to that slot.
- OCT- + OCT+ held 5 s: update mode (kept from Felucca, unchanged).

Whether the key light bars are drivable is unknown (Felucca only lights button
LEDs). The screen shows everything; key lights are a bonus if they work.

## MIDI (USB, class compliant)

- In: ch 10 GM drum notes play the kit; ch 4 notes 36-43 play break slices (BB Gen's map);
  ch 2 plays 303 A and ch 3 plays 303 B (note,
  velocity >= 100 = accent, legato overlap = slide); clock + start/stop/continue follow an external
  clock (auto: clock seen in the last 500 ms).
- Out: clock + transport when internal; the sequencer's notes on ch 10 / 2 / 3
  (GLO toggle, default off).
- The CDC serial console is OFF by default (one MIDI interface, the most widely
  accepted descriptor); `X0X_CDC=1` keeps it for debugging.

## Software structure

```
firmware/
  hal/ loader/               Felucca, unchanged
  src/
    x0x.c                    unity build entry (as felucca.c)
    platform/                lcd.c gfx.c libc.c usb.c storage.c ota.c — Felucca's, kept
    dsp/fastmath.h           expf/exp2f/tanhf/powf/sinf/logf approximations (no libm)
    dsp/drum909.{h,c}        9W9 engine port (float, no malloc, no libm, no double)
    dsp/bass303.{h,c}        Open303 port (float, polyBLEP oscillator, no tables)
    dsp/fxbus.{h,c}          send reverb/delay + master (from 9W9), shared by all parts
    dsp/breaks.{h,c}         slice player (ADPCM from the flash slots) + the generator
    seq/pattern.{h,c}        pattern model, 16 slots, chain
    seq/sequencer.{h,c}      clock, swing, step events -> drum triggers / 303 notes
    seq/tb3po.{h,c}          generator (port of schwung-tb3po's generate/mutate)
    app/ui_*.c               panel mapping, pages, drawing
    app/project.c            save/load to flash
host/                        the whole app on macOS/Linux: fake platform,
                             scripted input -> WAV + screen PNG frames
```

Rules carried over from Schwung/Felucca experience:

- **The audio ISR never touches flash, allocates, or waits.** UI writes to the
  pattern are single word stores or go through a small command queue drained at
  a block start.
- **No double in the audio path.** The FPU is float-only; a double op is a
  software call per sample. `tools/build.py` fails the build if the render path
  calls `__*df*` routines.
- **No libm.** `fastmath.h` is the only maths, so host renders and the device
  produce the same samples and the golden hashes hold on both.
- **The host build is the test bench.** Every part renders and is checked on the
  Mac; the screen is rendered to PNG and looked at.
- Cost is controlled by design: idle drum voices skip, the 303 oversampling factor
  is a build constant (default 2, Open303's own is 4), and the render path's
  instruction counts are budgeted like Felucca's `target_budget`.

## What needs the device

Boot and the FPU in practice; CPU headroom (render-time per half buffer) — two
303s plus the kit is the heaviest load, and the 303 oversampling factor is the knob; key LEDs;
USB enumeration; flash save/load. The firmware shows its audio load on the GLO page
and keeps Felucca's crash screen, so the first boot reports itself.
